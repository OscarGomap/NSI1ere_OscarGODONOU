# 5.4 Protocoles de communication dans un réseau

!!! note "Cours"
    Pour que des machines communiquent, elles doivent suivre des règles
    communes : les **protocoles**. Les échanges sur Internet reposent sur
    un modèle en **couches**, chacune ayant un rôle précis :

    | Couche | Rôle | Exemples de protocoles |
    |--------|------|-------------------------|
    | Application | Format des données échangées | HTTP, DNS, SMTP |
    | Transport | Découpage en paquets, fiabilité | TCP, UDP |
    | Réseau | Acheminement (routage) | IP |

!!! example "Le rôle du DNS"
    Le **DNS** (Domain Name System) traduit un nom de domaine
    (`www.exemple.fr`) en adresse IP compréhensible par les machines.

!!! tip "TCP vs UDP"
    **TCP** garantit que les données arrivent complètes et dans l'ordre
    (utilisé pour le web, l'email). **UDP** est plus rapide mais sans
    garantie de fiabilité (utilisé pour la vidéo en direct, les jeux en
    ligne).

## Activité

1. Utiliser la commande `nslookup` (ou un site en ligne) pour trouver
   l'adresse IP associée à un nom de domaine.
2. Expliquer pourquoi le streaming vidéo peut tolérer UDP alors qu'un
   téléchargement de fichier a besoin de TCP.

## Exercices

1. Que se passe-t-il si un paquet est perdu en TCP ? Et en UDP ?

??? abstract "Correction"
    En **TCP**, le protocole détecte la perte et **retransmet** le paquet
    manquant pour garantir l'intégrité des données. En **UDP**, aucune
    retransmission n'a lieu : le paquet perdu est simplement ignoré, ce qui
    peut créer un défaut ponctuel (image figée, coupure sonore) sans
    bloquer le flux.
